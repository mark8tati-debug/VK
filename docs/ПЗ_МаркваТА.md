# Пояснительная записка: веб-приложение «Квизы»


---

## 1. Цель и результат

Разработан прототип (MVP) платформы для проведения квизов в реальном времени. Организатор создаёт и настраивает опрос, запускает сессию по коду комнаты; участники подключаются, отвечают только на активный вопрос; по завершении отображается лидерборд, данные сохраняются в БД.

## 2. Обоснование средств разработки

| Слой | Технология | Обоснование |
|------|------------|-------------|
| UI-проектирование | Figma, Miro | Быстрое согласование сценариев, прототипирование до кода |
| Клиент | **React 18 + Vite + JavaScript** | Компонентная модель, экосистема, соответствие требованию «популярный фреймворк» |
| Стили | **CSS (custom properties)** | Палитра и компоненты по макетам Figma 1440px |
| Сервер | **Node.js + Express** | Единый язык с клиентом (JavaScript), простота MVP |
| Real-time | **Socket.IO** | Комнаты, синхронизация вопроса и ответов, опыт из ТЗ |
| БД | **SQLite + Prisma ORM** | Реляционная модель для MVP без отдельного сервера БД |
| Авторизация | **JWT + bcrypt** | Роли участник / организатор |

**Альтернативы:** Next.js (full-stack), PartyKit — отложены на этап масштабирования; для MVP выбран раздельный client/server для явного разделения WebSocket-логики.

## 3. Этапы разработки (по алгоритму ТЗ)

1. **UI (Figma)** — лендинг, auth, дашборд организатора, редактор вопросов, live-сессия, участник, лидерборд, ЛК. Прототип на странице `08 · Прототип`.
2. **Модель БД** — см. `quiz-platform/server/prisma/schema.prisma`: User, Quiz, Question, Option, QuizSession, Answer, SessionParticipant.
3. **Веб-интерфейс** — `quiz-platform/client`: маршруты `/login`, `/register`, `/dashboard`, `/quiz/:id/edit`, `/host/:sessionId`, `/join`, `/play/:sessionId`, `/results/:sessionId`.
4. **Серверная часть** — REST API + Prisma; валидация, RBAC.
5. **WebSocket** — события: `join_session`, `show_question`, `submit_answer`, `end_question`, `end_session`.
6. **Тестирование** — чек-лист сценариев (организатор + 3–5 участников), фиксация багов.

## 4. Функциональное соответствие требованиям

| Требование | Реализация в MVP |
|------------|------------------|
| Регистрация / авторизация (участник, организатор) | `POST /api/auth/register`, `POST /api/auth/login`, поле `role` |
| Создание и настройка квиза | CRUD квиза, категории, `timePerQuestion`, `answersOnlyWhenShown` |
| Типы вопросов | `TEXT` / `IMAGE`, `SINGLE` / `MULTIPLE`, варианты в `Option` |
| Код комнаты, live | `QuizSession.roomCode`, Socket.IO room, флаг `isQuestionActive` |
| Баллы и победители | `score = base + speedBonus`, лидерборд по `SessionParticipant` |
| Личный кабинет | История участия и проведённых сессий по `userId` |

## 5. Риски и дальнейшее развитие

- **Риск:** рассинхронизация таймера — mitigated серверным источником времени в Socket.IO.
- **Риск:** нагрузка при масштабе — MVP рассчитан на пилотную группу (до 50 участников в комнате).
- **Далее:** OAuth/SSO, медиа-хранилище для изображений, аналитика, мобильная адаптация 375px.
